# Daat Locus 0.4.0

## Highlights

- Added first-class Lua workflows for orchestrating isolated agent workers with typed inputs and outputs, ordinary Lua control flow, host App tools, and workflow-local tools.
- Added workflow execution inspectors to both TUI and WebUI, including run graphs, actor attempts, transitions, status, timing, and worker activity.
- Added built-in `goal` and `search` workflows, plus persistent workflow actors that retain their worker-local conversation and App state across sequential runs.
- Added a local `view_image` runtime tool so vision-capable models can inspect images already present in the workspace.
- Improved session presentation with non-blocking AI-generated titles, worked-duration indicators, syntax-highlighted Markdown code blocks, and responsive wide tables.
- Improved Coding and provider reliability with non-SCOPE structured-edit fallback, non-blocking LSP response handling, and provider-independent request downgrade retries.

## Lua Workflows

- Added a Lua 5.4 workflow runtime for executable, side-effectful orchestration programs.
- Added typed `workflow__<id>` tools for the main agent and generated input forms for interactive use through `/workflows`.
- Added isolated workflow workers with their own conversation history, App instances, runtime state, and plans. Workers can use the main or efficient model and receive only their allowed host and workflow-local tools.
- Added `workflow.agent`, `workflow.await`, `workflow.await_all`, and `workflow.tool` primitives for sequential, concurrent, conditional, recursive, verification, revision, and retry flows.
- Added persistent actors: sequential runs of one actor retain worker-local history and App state until the workflow explicitly calls `actor:reset()`.
- Added transition labels for `await`, `verify`, `revision`, and `retry` handoffs.
- Removed the fixed worker turn limit; runs continue until they complete, fail, are interrupted, or reach an external runtime budget.
- Loaded user workflows globally from `~/.daat-locus/workflows/*.lua`, or `$DAAT_LOCUS_HOME/workflows` when `DAAT_LOCUS_HOME` is set.
- Added built-in `goal` and `search` workflows compiled into release binaries. A user file with the same id overrides the built-in definition.
- Added `examples/workflows/research_brief.lua`, English and Chinese workflow documentation, and the built-in `author-lua-workflow` skill.
- Kept interrupted workflow runs non-replayable by default because workflows may perform filesystem and process side effects.

## Workflow Inspector

- Added live and completed workflow run rows to session activity.
- Added TUI and WebUI inspectors for workflow status, input/output, errors, await groups, actors, worker attempts, execution timing, and transitions.
- Added a graph view in WebUI for actor relationships and verification/revision/retry loops.
- Persisted worker activity and added paged loading so older worker events can be inspected without embedding the entire stream in every dashboard snapshot.
- Added per-attempt worker activity views while preserving repeated runs of the same persistent actor as distinct attempts.
- Fixed workflow dashboard routing and inspector updates for session-scoped runs.

## Sessions and Runtime

- Added efficient-model session title generation after completed turns and changed activity, with signature-based deduplication to avoid redundant model calls.
- Moved title generation to a background task so it does not block the runtime scheduler.
- Added worked-duration metadata to completed replies in TUI and WebUI.
- Changed runtime context compaction to use the main model; the efficient model remains available for background work such as session titles and judging.
- Preserved conservative context-budget estimates when exact token information is unavailable.
- Preserved runtime failure fuses across retry attempts so repeated failures still stop safely.
- Unified built-in and workspace App tool execution contracts and isolated workflow workers from main-session event completion authority and workflow entry tools.

## TUI and WebUI

- Added `/workflows` selection and typed input flows in both clients.
- Rendered agent replies as one Markdown block instead of splitting the first line into a separate header.
- Added syntax highlighting for fenced Markdown code blocks in TUI.
- Made wide Markdown tables responsive in WebUI.
- Added workflow run and worker activity inspectors with live status and timing.
- Fixed a TUI panic when a wrapped activity prefix exceeds the available width.

## Runtime Tools and Coding

- Added `view_image` for sandbox-checked local PNG, JPEG, WebP, and GIF files up to 10 MiB. The tool is exposed only when the selected model supports image input.
- Added the same image-inspection capability to vision-capable workflow workers.
- Allowed `coding__edit_code` to fall back to plain structured file edits for files outside SCOPE parser ownership, while retaining parse validation and propagation review for supported source files.
- Added structured edit support for ordinary non-SCOPE files without requiring agents to switch editing contracts.
- Allowed `coding__read_code` to accept a line number without a hash when only location-based reading is needed; edit anchors remain hash-validated.
- Fixed LSP response handling so server notifications cannot block response delivery.

## Models and Providers

- Replaced provider-error-text matching with a deterministic HTTP 400 downgrade pipeline for tool-choice and thinking-budget representations, improving compatibility with OpenAI-compatible gateways such as opencode-go and Console Go.
- Fixed reasoning option selection for providers that do not match a known models.dev provider entry.
- Downloaded the current `models.dev` catalog during builds and compiled that snapshot into the binary, while retaining runtime cache refresh and conservative fallbacks.
- Persisted imported Codex OAuth credentials into Daat-owned private files and recorded the selected `auth_file` in provider configuration.
- Added Codex OAuth file selection to the WebUI setup flow.

## Fixes and Reliability

- Propagated daemon token permission errors instead of silently continuing with unusable authentication state.
- Returned explicit errors when the configured sandbox backend is unavailable.
- Fixed cross-platform CI regressions in daemon tray, persistence, workflow, workspace App, and sandbox code.
- Gated platform-specific sandbox helpers correctly on Windows, Linux, and macOS.
- Updated the Markdown renderer submodule and removed unused renderer and publish artifacts.

## Compatibility and Migration Notes

- Lua workflows are a new runtime subsystem in 0.4.0 and are distinct from skills. Skills remain Markdown guidance; workflows are executable orchestration programs.
- Workflows are shared across sessions from `~/.daat-locus/workflows`. Reloading skills also reloads the workflow catalog.
- Untouched legacy `goal.lua` and `search.lua` installer copies are moved to `~/.daat-locus/workflows/legacy-builtin-workflows/` on reload so they do not shadow the current built-ins. Modified files remain explicit user overrides. Existing backup conflicts must be resolved manually.
- Existing Codex OAuth provider files are migrated from the legacy config directory into `~/.daat-locus/codex-auth`, and `auth_file` is written into `config.toml`. Explicit custom auth paths are preserved.
- Workspace App hook compatibility is unchanged for `config`, `init`, `render_state`, `list_tools`, `call_tool`, and `poll_notices`.
- Source builds now require network access to `https://models.dev/api.json`; `build.rs` uses an unpinned live response with a 30-second timeout and fails the build if the catalog is unavailable, empty, or invalid.

## Dependencies

- Enabled `mlua`'s `send` feature for workflow execution across async worker tasks.
- Added `@xyflow/react` and `@dagrejs/dagre` for the WebUI workflow graph.
- Updated the bundled `daat-locus-md` submodule.

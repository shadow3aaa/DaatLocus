# 架构与接口

本文定义 Actor/App 系统的产品结构、执行与恢复策略，以及账号、设备和客户端接口契约。
工程约束见 [AGENTS.md](../AGENTS.md)；构建、测试与发布流程见[贡献指南](../CONTRIBUTING_zh-CN.md)。

## Actor 与 App

`Actor = Agent 核心 + 安装的 App 实例`。`src/actors` 负责串行收件箱、
模型执行、持久上下文、审批与回复；不同 Actor 并行推进。App 是唯一工具抽象，
各领域自行定义查询与操作，不要求统一 `get_state`。

业务数据不设固定总量配额：Actor 总数与所有权层级、导入对话的字节数、记录数和
消息数、MCP 安装与工具数、权限列表以及 Files/Skills 的扫描数量和深度均不以
常量截断或拒绝。内容缓存按目标容量回收冷数据，但不因单个资源大小或活跃传输
超过目标而拒收；快照和恢复归档不设历史总字节数配额。分页、单帧传输、背压、
认证防滥用、模型预算、文件访问和授权校验仍各自生效，分页大小不是业务总量上限。

`src/builtin_apps.rs` 安装 Actors、Files/Skills、Terminal、Browser、Artifacts。
各 App 的指令统一维护在 `src/app_instructions`，工具描述和可移植输入
schema 留在所属 App。Skills 是可发现、读取的指令资源，不拥有独立执行引擎。

Study 已移除。加载持久 Actor 配置时移除旧能力列表，普通 Actor 直接使用设备全量
App，Core 只构造 Actors App；保留身份、历史、输入和工作目录，不恢复旧应用。

`src/app_instructions/orchestration.md` 维护通用场景的 Actor 分工、复用、
工作区协作与结果验收策略，与 Core 和普通 Actors App 的指令共同编译并
注入模型上下文。它是模型的
决策指导，不引入固定工作流、调度引擎或额外授权，权限与持久路由仍由代码执行。

Actor 的创建、工作目录、App 安装集合和沙箱范围是内部状态。客户端只能切换
模型偏好与 Full access / Ask / Auto；模型不能修改批准模式。所有 Actor 持续
保留身份、配置、上下文与历史，没有单独删除入口。完成任务、退出账号、停止进程
或释放 App 资源不删除 Actor。

Core 的 Actors App 提供 `archive` / `unarchive`，仅响应 Owner 对目标 Actor 的
明确请求，不要求审批；协作者输入、历史材料和只读远程权限不能触发此操作，Core
本身不可归档。归档在目标宿主执行，与消息入队共用数据库事务：Actor 必须 idle，
没有排队/执行中的输入或尚待返回的委派。归档状态持久保存，通过 ActorChanged
事件传播；保留身份、配置、上下文、历史、权限和资源，所有入口均拒绝新消息。
对话仍可查看，输入框显示已归档。取消归档只恢复接收消息，不恢复或重放旧工作；
重启、App 回收及模型配置变化不得取消归档。

Owner 可在账号设置中确认重置整个账号的工作数据：先停止执行与审批，再清空全部
Actor、会话、历史、内部资源与权限，并按初始策略重建 Core。模型配置、账号凭据、
设备身份及连接、撤销记录、Raft 投票与成员关系和工作目录文件保留。重置记录由具备
账号授权能力的设备签名，由当前有权管理账号的设备发起或转发，与本机数据清理在
同一事务中保存；签名设备后来被撤销不回滚已生效的重置。内部 App 与附件文件的
清理标记在重启后继续完成。重置按单调修订与签名设备排序，连接在交换业务数据前
核对重置代次，离线旧副本先清理后重连，不能重新导入旧历史、权限或重放操作。
Raft 中的新代次清空旧执行租约与工作 head，不重建投票或成员关系，并保留已同步设备
的本地恢复资格。重置不提供模型
工具，不允许按 Actor 删除；客户端须输入账号名确认，重置后清除会话草稿并返回 Core。

提供商始终可删除，关联模型一并移除；仍有效的默认和审批模型选择保留，失效选择
按模型列表顺序回退，审批默认继承主模型。配置持久化成功后，使用已移除模型的
Actor 偏好回到账号默认，其他配置与历史不变。删除最后一个模型可以保存为未配置
状态，排队输入保留、推理不启动；私密设备同步传播相同定义。HTTP 保存使用服务
所属 profile 的配置与备份，不依赖进程全局配置目录。

OpenCode Console OAuth 在发送模型请求前解析工作区选择，成功后写回私有凭据文件，
由模型推理与模型目录查询共享。查询失败不发送缺少工作区标识的推理请求，也不缓存
不完整授权；保留认证、连接、限流与服务错误分类。凭据刷新先持久化新的令牌，
后续工作区查询失败仍保留已轮换的凭据。
Zen/Go 直接 URL 的 Chat、Responses 与 Anthropic 接口共享网关身份与失败分类；
模型不可用及地区拒绝立即终止，临时上游故障保留重试。工具别名只映射实际可用的
唯一 App 操作，保留设备前缀与原始约束，不补充不存在的执行能力。

Actor 的持久身份与 worker 驻留分离。启动、账号激活和恢复执行只查询有可执行
输入的收件箱；创建 Actor 和读取对话不会启动 worker。入队后按需激活，同一
Actor 仍只有一个串行 worker。没有输入持续 60 秒后，可安全重建的 App 关闭，
worker 与注册表条目释放；再次入队从 SQLite 加载配置、上下文锚点与历史。
空唤醒不延长空闲期限。收件箱的部分索引只包含排队输入，避免启动时扫描全部历史。

App 默认不允许空闲回收，必须明确声明自身可安全重建。Actors、Files、Artifacts
和只读 HTTP 缓存允许回收；终端保留会话或输出、浏览器保留上下文时阻止
回收，不杀进程、不丢页面或会话数据。终端使用随机唯一会话 ID，重建后不复用旧引用。
这些资源仍通过已有关闭操作或显式生命周期停止释放，空闲回收不重放 App 操作。
App 关闭期间 worker 仍占据注册表位置，关闭完成后移除并重查持久收件箱，避免
并行实例与丢失唤醒；暂停、重配置和退出在同一注册表锁下阻止新 worker。
共享 Core 的激活继续检查设备执行授权，无租约时保留输入而不驻留等待 worker。
Actor 列表在 SQLite 内按 ID 游标分页；容量、模型引用校验和私有目录边界查询
只读取计数、模型名或 ID，不加载全部配置。历史分页加载时直接借用消息计算预算，
只为通过预算检查的模型请求复制工作窗口，不为每页构造临时完整请求。

## Windows Virtual Workspace 基础设施

`crates/daat-locus-virtual-workspace` 是可独立构建的 lib crate，不依赖 Actor、
账号存储、WebUI 或 Tauri。Windows ComputerUse App 在服务内使用此库；Core 的
工具集合仍只有 Actors App。`driver/` 是自有 Rust `cdylib` UMDF 2.25 / IddCx 1.4 驱动，使用独立
Cargo 构建图；工作区 `xtask idd-driver` 准备固定版本/哈希 WDK、调用 Cargo 编译、
Inf2Cat 打包及签名，不使用独立 PowerShell 构建脚本。开发包默认复用本机
`.dev/windows-signing/` 中的开发身份，私钥备份仅当前 OS 所有者可读，并通过
CurrentUser DPAPI 保护随机 PFX 密码。构建只准备 CurrentUser/My 签名身份，
不建立系统信任；debug 安装 helper 在构建时固定对应公钥。release 构建必须
提供签名身份，发行 helper 始终固定仓库公钥，不接受开发身份覆盖或自动回退。
Windows 10 1903+ x64，驱动消费并释放 swap-chain 帧，桌面捕获由 lib 完成。
`DriverPackage::install` 经正常 PnP 安装一次驱动与持久适配器，需要 OS 管理员
权限，允许系统发布者确认。先注册根枚举设备节点再安装/绑定，首次安装不依赖旧节点。
库的普通部署 API 不修改证书存储；发行 helper 显式向 LocalMachine Root 与
TrustedPublisher 导入嵌入的专用自签名代码签名公钥证书，安装页面说明该行为。
helper 在导入前用固定公钥验证 CAT 签名，导入后验证 INF/DLL 的目录成员签名；
不接受包旁边的任意证书或调用方指定的信任身份。私钥不进入源码或安装包。
机器级互斥与按嵌入证书 SHA256 分隔的 HKLM 持久记录串行化安装、保留已有信任；失败回滚本次新增信任，
PnP 部分部署失败先回收新增驱动包，不能在驱动仍需重启清理时提前撤销信任。
Burn 按 CAT SHA256 和两处证书存在状态检测已部署版本，客户端 MSI 保持 per-user；
驱动 ExePackage 的 InstallCondition 在版本与信任均满足时跳过整个永久前置包，
Repair（Burn action 8）仍执行修复，实际部署保留安装文件缓存供维护。
只设置 DetectCondition 不足以跳过缓存：Burn 6 会缓存请求为 Present 的包，
在没有提权执行的计划中写入 ProgramData 而失败；也不应无条件计划机器缓存清理。
不通过放宽系统缓存目录权限解决此问题。
卸载某个用户客户端保留共享驱动。显式完整驱动卸载移除 DL 适配器和该身份的
所有已存储版本，再删除安装器拥有的信任项；已有信任不删除，需要重启时延后清理。
不修改 Secure Boot、测试签名、内存完整性或签名强制策略，首次下载提示仍可能出现。
安装/加载兼容性仍须在干净目标系统验证；自签信任不等于微软认证。
安装和证书管理不能暴露为 WebView 原生命令或 Actor 工具。

`VirtualDisplay::create` / `VirtualWorkspace::create` 不要求预先存在虚拟屏：
库通过设备接口 CreateFile / IOCTL 创建属于该文件对象的监视器，无管道、额外
守护服务、全局屏幕数量设置或心跳保活。适配器同时支持至多 8 个监视器。
驱动从 IddCxMonitorArrival 返回实际 adapter LUID 与 target ID，lib 按这两个值
匹配 DisplayConfig，不能按连接器索引、显示名称或“新增的第一个屏幕”猜测归属。
驱动协议使用固定宽度、版本化字节消息，不传进程指针或 Rust 原生布局。
自定义 IOCTL 经 IddCx 的 EvtIddCxDeviceIoControl 转发，不另建默认 WDF 队列。
DisplayConfig 的查询与配置统一使用 VIRTUAL_MODE_AWARE；旧式查询会映射 IDD 的
adapter/target，不能用于归属匹配。虚拟模式路径分别编码源、目标和 desktop-image
索引，保留其他路径的模式引用；间接显示由目标 base output technology 识别，
不能由驱动报告的连接器类型推断。
库在捕获、放置和输入前通过原文件对象查询监视器租约，防止设备恢复后复用的
LUID/target ID 被旧 workspace 误认领；关闭文件后排队的创建请求也必须拒绝。
支持 720p 至 4K 的五种 60 Hz 模式，
可配置分辨率和位置；SetDisplayConfig 保留其他活动路径及显式源/目标模式，不使用
全局 Extend、不允许自动改动其他输出模式，也不写用户的持久布局。重叠位置拒绝。
默认选择与独立物理屏相邻且未占用的位置，优先右侧，不把多个工作区排成依赖
前一屏存在的长链；找不到空位时要求显式位置。独立物理屏必须保持启用。

每个 workspace 独占一个非继承设备句柄。构造失败、析构或进程退出关闭最后句柄，
驱动 EvtFileCleanup 只拔除该文件对象的屏幕，显式 remove/close 等待输出移除。
正常 remove/Drop 先用 DisplayConfig 停用自己的活动路径、保留其余源/目标模式，
再关闭设备句柄，避免热拔除触发 Windows 重排其他输出；等待移除同时检查
targetAvailable 和路径活动标记。进程被强杀时没有这一步用户态停用过程，
由驱动文件清理拔除屏幕，布局变化仍由 Windows 处理。
睡眠/设备停机退休适配器代次及所有屏幕；旧句柄清理不能移除新代次屏幕，
恢复后不自动重放旧 workspace 的创建或输入。关闭屏幕不卸载适配器/驱动包。
attach 仅借用现有输出，
不能配置或删除该输出。DisplayConfig 的 adapter LUID、target ID 和 monitor device path 标识目标，
每次操作重新检查显示几何和拓扑；镜像输出以及没有独立物理显示器的环境拒绝连接。

窗口引用绑定 HWND、PID、进程创建时间、GUI 线程和观察时的物理像素几何。
放置窗口使用不请求激活的异步 SetWindowPos；调用方重新观察后才能输入，不隐式
还原最小化/最大化窗口。库保留 GDI 整屏诊断捕获；生产 ComputerUse 通过
`Window::capture` 使用 WGC 捕获指定 HWND 的合成表面，返回原始 BGRA 像素。
受保护、排除捕获或最小化窗口不保证可用，不以整屏裁剪回退。

输入通过 CreateSyntheticPointerDevice / InjectSyntheticPointerInput 创建真实
touch contact，由 Windows 命中测试、捕获并生成可用 GetPointerInfo 读取的
WM_POINTER 消息；不伪造 pointer 消息，不使用鼠标/键盘 SendInput 或恢复用户焦点。
此原生触摸路径与下面的可选 DLL Hook 路径独立。每个实例串行管理一个 contact 的
Down/Move/Up/Cancel，活动 contact 不能换窗。目标窗口必须完整位于工作区，
输入点必须命中其客户区；显示变化、窗口变化和遮挡均在操作前拒绝。
取消只释放自己的 touch 状态；析构随后回收自己拥有的屏幕，不关闭应用或删除 Actor 数据。

Windows 接受输入只代表接受合成帧，不证明目标应用已执行。输入前后分别观察
前台、键盘焦点和光标，跨操作比较前台/焦点；发现变化后中断后续输入，允许取消。
这些快照不能证明观察间没有瞬时焦点变化。WM_POINTERACTIVATE、触摸到鼠标的
兼容转换和目标应用行为仍可能激活窗口；原生触摸不提供独立键盘。
调试夹具区分自行处理 PA_NOACTIVATE 的 pointer-aware 窗口与默认激活
行为，前者通过不能推导第三方应用也通过。自建 IDD 上的默认 pointer 激活用例
也覆盖 WS_EX_NOACTIVATE：该样式不替代接收窗口处理 WM_POINTERACTIVATE。
库不修改目标窗口样式来声称焦点隔离。未知效果必须重新观察，不自动重放。

`hook/` 是普通 Cargo workspace 成员 `daat-locus-workspace-hook`，产出 Rust
cdylib；不修改系统 DLL、内核或目标磁盘文件。`WindowHook::attach` 热加载调用方
明确提供的 DLL，在目标进程的指定 GUI 线程安装 WH_CBT / WH_GETMESSAGE；
不安装桌面全局 Hook。当前仅接受与控制端相同架构的目标，且控制端必须处于
目标进程之外。`VirtualWorkspace::hook` 额外检查安装时目标完整位于工作区。
这一路径明确允许向目标进程加载 DLL；应用无需预先适配，但可能限制 DLL 加载。
CBT 在已安装 Hook 的 GUI 线程中，按真实窗口归属否决指定顶层窗口、子控件及 owned
窗口的激活/焦点请求；请求目标可以来自另一个 GUI 线程/进程。输入命令仍须在目标
自身线程执行。独立兄弟窗口不受该策略约束，不恢复用户焦点。守卫 close/Drop
先禁用策略，再卸载 Hook；不承诺立即卸载 DLL。

可视顶层窗口与输入表面分别建模。`InputSurface` 通过真实子窗口/owner 关系归属
顶层窗口，绑定自己的 HWND、进程创建时间、GUI 线程与 class；不要求内容与框架
具有同一 PID/TID。`WindowHook` 持有各实际 GUI 线程的租约，命令投递到对应表面，
重新观察时回收失效内容线程并发现新表面。归属判断不因相同 PID 授权独立兄弟窗口。
接管、观察和派发前，App 同样检查内容进程的自身进程/私有路径排除边界。
输入接收者绑定完整表面身份及新观察中的几何信息，不能仅凭 class 继续使用旧路由。

安装前读取目标二进制签名策略；纯 Hook API 对 Microsoft/Store-only 策略返回类型化
错误，而非等待无效握手或要求 Agent 重新点击。`WindowInput` / `VirtualWorkspace::input`
仅在接管阶段遇到该错误时选择 UI Automation；操作已经开始后绝不更换后端重放。
UIA 使用 `CUIAutomation8`，显式关闭 `IUIAutomation2::AutoSetFocus`，并设置有界连接/
事务超时；不调用 SetFocus。仍在允许注入的框架/内容线程保留 CBT 守卫，受签名策略
保护的内容进程不加载自研 DLL。真实 Calculator 算术验收与纯 Hook 签名策略拒绝
测试均属于独立库的 opt-in 原生测试；前者检查实际显示的 7 + 5 = 12、桌面输入保持
与撤权，后者检查拒绝发生在输入之前并回收部分安装的租约。

UIA 坐标从实际原生输入表面换算为物理屏幕位置，命中元素必须同时满足受控原生进程
身份和 UIA 树中的窗口归属。左键操作调用 Invoke/Toggle/SelectionItem/ExpandCollapse
模式，垂直滚动沿受控祖先查找 Scroll 模式，关闭使用 Window 模式；不调用测试端的
Invoke 来伪造生产输入。缺少模式在派发前明确拒绝。UIA 后端不声称支持通用按键、
插入位置 Unicode 文本或指针拖曳，也不把替换整个 Value 冒充插入文本；观察中的
supported_actions 反映实际后端。COM 错误或焦点/capture 变化停止后续输入并保留
未知效果，不恢复桌面状态来掩盖干扰。UIA 接口调用完成不证明任意软件的异步业务完成。

同一 GUI 线程只允许一个 Hook 租约。控制端与 DLL 通过会话内、默认 OS 访问控制、
非继承的命名文件映射交换版本化定长命令，无进程指针、管道或额外服务。
目标/控制端 PID 与进程创建时间、目标 GUI 线程、可视根窗口及其进程/线程身份、
传输表面、随机唤醒 token 共同约束操作；DLL 确认控制进程仍存活。
目标根窗口或传输表面销毁会禁用该租约。交还时先禁用组内所有租约，再逐一等待/卸载；
内容进程已退出后，系统移除其 Hook 不应阻止回收或重新绑定。
发布/认领/完成/取消以原子状态传递 payload 所有权，每条命令只认领一次；
超时取消尚未开始的命令，已开始的效果视为未知，禁用租约并拒绝后续输入，不重放。
首次握手确认回调确实在目标线程执行，不能把 SetWindowsHookEx 成功等同于可用。

Hook 文本操作在目标线程对明确子控件派发 UTF-16 WM_CHAR；键操作派发
WM_KEYDOWN/UP，并临时设置、恢复该 GUI 线程键盘状态，支持 Shift/Control。
它不执行应用消息循环的 accelerator 翻译，不提供 Raw Input、系统快捷键或
GetAsyncKeyState 虚拟化。鼠标操作按控件客户区坐标派发 move/left click/wheel
消息，不移动真实光标；click 的 down/up 在单次回调中完成。
`WindowHook::drag` 接受 2..=128 个 signed-16-bit 控件客户区坐标，先校验整条轨迹，
起点必须在客户区内，后续点可移出客户区。按下、携带 MK_LBUTTON 的移动和抬起
在单次目标线程回调中完成，不 sleep、不跨命令持有按键，不提供 OLE drag/drop。
手势守卫在异常结束时派发 WM_CANCELMODE，并释放仅属于目标窗口树的 capture；
超时仍遵守未知效果不重放约定。协议 ABI 为 4，旧 DLL 在安装 Hook 前拒绝。
关闭窗口也在追踪的目标线程命令内同步派发 WM_CLOSE，不遗留可在交还后执行的关闭消息。
已有鼠标 capture 时拒绝 click/drag；原生控件仍可能在同步手势内短暂取得真实
capture，因此不承诺用户同时拖拽的独立性。GetFocus/GetCursorPos 等查询没有虚拟化。
回执只证明派发及前后桌面观察，不证明任意应用执行成功或不存在瞬时干扰。
标准 EDIT/BUTTON/trackbar 的跨进程夹具只验证这些控件；默认触摸兼容转换在 CBT 拦截下
仍可能移动系统光标，不能作为无干扰鼠标后端。ComputerUse 使用 Hook 或 UIA 输入，不回退到触摸。

## ComputerUse App（macOS）

macOS 与 Windows 共用 `computer_use` 设备 App、工具名称、模型 schema、Actor
归属检查及设备桌面能力审批。Core 仍仅持有 Actors App；Android 保留 `phone_use`。
macOS 原生宿主位于独立的 `crates/daat-locus-computer-use` lib，不依赖 Actor、
账号存储、HTTP 或 Tauri。`daat-locus-client-protocol::computer_use` 定义有界通信
封包及 macOS Unix socket 客户端，不链接 AppKit / ScreenCaptureKit；服务只依赖此
协议。Tauri 客户端拥有原生宿主与系统授权身份，退出客户端释放窗口引用，独立服务
继续运行；GUI 操作必须等待客户端重新打开。此能力不创建或移动窗口到虚拟屏幕。

Owner 在独立的“GUI 操作”设置中启用，再按弹窗授予辅助功能与屏幕录制。
授权按钮请求系统权限并打开对应隐私设置页，兼容系统不再重复弹出请求的情况。
三项原生命令仅允许已认证 Owner 的主 WebView 调用，不向 JavaScript 开放截图、
AX 对象、进程或通用系统调用。启用状态按设备 profile 原子保存；关闭先撤销新的
输入准入，并在已开始的调用结束后清理引用。OS 授权撤销时后续操作拒绝，不替用户
修改 TCC、系统安全设置或提示授权。完整后台截图需要 macOS 14+；旧系统仍可运行
客户端，GUI 功能返回不可用。

原生宿主通过 profile 私有的 `runtime/computer-use.sock` 接受服务请求，socket
权限为 0600，双方核对 OS UID、`LOCAL_PEERPID` 及伴随可执行文件的精确路径。
请求不超过 64 KiB，回复不超过 48 MiB，连接有时限及并发上限。每个 Actor 保留独立
会话、单调执行 epoch、不可猜测的应用/窗口/截图引用；窗口获取不能跨 Actor，
释放或会话变化使旧引用失效。取消、过期 epoch、权限关闭和陈旧图像在发出下一项
原生操作前检查；已开始的输入或启动若结果不确定，返回 `outcome_unknown`，禁止重放。

截图使用 ScreenCaptureKit 的单窗口过滤，允许遮挡窗口，隐藏真实光标；最小化
窗口不作为实时来源。完整窗口、裁剪和放大均有 800 万像素上限，输入从返回图片
像素映射到 AX 桌面逻辑点。输入前核对原进程启动身份、原生窗口编号、AX 窗口对象、
几何及可访问控件状态。窗口编号绑定使用可选 `_AXUIElementGetWindow`，系统不提供
该符号时拒绝精确绑定，不猜测同名窗口。

当前输入路由为 AX 原生控件操作：按钮 Press、显式选定可编辑控件的 Unicode
插入与受支持的编辑键、可写滚动条、滑块拖动，以及窗口位置、大小、恢复和关闭。
观察返回有界控件事实与支持的操作；自绘控件、不支持的键或轴拒绝输入，不回退到
全局 CGEvent、剪贴板、激活窗口或移动物理光标。后台启动使用
`NSWorkspace.OpenConfiguration.activates=false`，仅获取该次新进程唯一确认的新窗口；
已运行应用要求先枚举窗口。每项原生调用比较前后台应用及真实指针，变化时报告
需要重新观察，不做“抢焦点后恢复”的补偿。目标应用主动弹出或激活窗口仍可能
导致结果不确定，不能据此声称所有应用均支持无干扰输入。

## ComputerUse App（Windows）

Windows x64 提供 `computer_use` 设备 App，普通 Actor 按现有规则获得，
Core 仍仅直接持有 Actors App。macOS 复用同一个 App，Android 使用 `phone_use`。
采用窗口定向的“发现、选定、观察、单次操作、再观察”交互；工具沿用现有 App
执行机制，不新增 JavaScript REPL、工具引擎或 Actor 类型。

Agent 不管理驱动、DLL、显示器编号、分辨率、Hook、HWND 或设备 IOCTL。
接管窗口时，App 在服务准备的共享虚拟屏中分配独立窗口区域并建立输入租约；运行资源由
专用 Windows OS 线程持有，App 通过有界类型化请求串行调度。共享设备注册表
协调窗口/GUI 线程租约；冲突返回 busy，不让两个 Actor 同时操控同一目标。
服务不创建展示窗口，不依赖 Tauri 事件循环，也不新增常驻管道服务。

### 工具与窗口生命周期

工具前缀为 `computer_use__`。Rust 输入类型使用
`model_schema` / `model_schema_for`，可选属性使用 required nullable 字段；
轨迹点使用 `{x,y}` 对象数组，不使用坐标元组或带 payload 的动作联合类型。

| 操作 | 输入要点 | 行为 |
| --- | --- | --- |
| `list_apps` | query、cursor、limit | 有界枚举可发现应用，返回 opaque app_id 和名称 |
| `list_windows` | app_id、cursor、limit | 有界枚举具体窗口，返回 opaque window_id、标题、归属、模态关系和接管状态 |
| `launch_app` | app_id | 先分配虚拟屏区域再启动；唯一、可归属且已出现在虚拟屏的新窗口直接接管并返回截图，否则返回未确认结果 |
| `open_window` | window_id | 明确接管这个窗口，放到虚拟屏、取得 Hook 租约并返回首个观察 |
| `get_window_state` | window_id、region、scale | 默认返回完整窗口截图；支持窗口内区域和整数放大，返回 state_id、可用操作和输入接收目标 |
| `adjust_window` | window_id、state_id、action、width、height、x、y | 非激活调整受控窗口：resize、move、fit、restore；返回完整窗口观察并清除旧输入路由 |
| `click` | window_id、state_id、x、y、button、click_count | 根据观察坐标解析实际控件并派发点击 |
| `type_text` | window_id、state_id、text | 向已选定的窗口内输入接收目标提交字面 Unicode 文本 |
| `press_key` | window_id、state_id、key | 向该输入接收目标派发按键或组合键 |
| `scroll` | window_id、state_id、x、y、delta_x、delta_y | 在指定位置解析接收控件并滚动 |
| `drag` | window_id、state_id、path | 在当前返回图像坐标中执行有界左键轨迹，由宿主转换裁剪和倍率 |
| `give_window` | window_id、state_id、placement | 撤销控制引用并向物理屏交还窗口；支持原位、居中、左半屏、右半屏 |
| `release_window` | window_id | 释放接管、Hook 和输入路由，不发送关闭应用指令 |
| `close_window` | window_id、state_id | 明确请求关闭该窗口，可能产生未保存确认对话框，不结束整个进程 |

`open_window` 是明确改变窗口位置的操作；枚举和观察不自动接管。运行中的应用
可能只有用户正在使用的窗口，不能因应用名匹配就移动它。启动也可能被应用转交给
已有实例；启动前记录所有顶层 HWND（包括隐藏窗口），返回候选来自真实枚举，
不把原有窗口重新显示冒充新建窗口。新窗口按启动回执的 PID/进程创建时间，或
Shell 目标 AUMID 与根/实际托管内容进程的系统应用标识对应；不能仅按标题或启动
期间全局新增窗口猜测归属。回执不含服务凭据。
启动前即建立共享虚拟屏并保留区域。临时自身子命令在清理的环境中启动：EXE 用
CreateProcessW 的 STARTF_USEPOSITION/STARTF_USESIZE/STARTF_USESHOWWINDOW 设置初始坐标、尺寸和
SW_SHOWNOACTIVATE，不继承句柄；Shell App 使用虚拟屏内隐藏非激活 owner，传入
SEE_MASK_HMONITOR 和目标 HMONITOR。不将虚拟屏设为主屏，也不通过设置用户光标/
前台来选择启动位置；首次增屏仍受 Windows 热插拔重定位边界约束。
在虚拟屏上确认唯一、可归属的新窗口后，沿用这次分配区域取得输入租约并返回首个
图像；无需模型再调用 open_window。应用仍可覆盖启动位置/激活提示或复用已有实例，
此时返回 outcome_unknown，不自动挪动用户原有窗口，也不通过事后恢复前台掩盖问题。
启动提示不是任意第三方应用首帧位置的强制隔离；观察位置与首次显示测试分开验证。
当前 Calculator 会忽略 Shell 显示器提示并激活到物理屏；此类启动未满足首帧虚拟屏
要求，按未确认结果处理，不能因其他 EXE 的首次显示测试通过就宣称通用支持。
启动、接管等改变状态的操作在需要观察确认时也返回当前窗口观察。

窗口 ID 由宿主登记，绑定设备、Actor、租约代次及真实窗口身份；不能由模型构造
原生句柄。进程创建时间、GUI 线程、窗口销毁和几何变化继续在执行时校验。
owned 模态/弹出窗口作为相关窗口返回，具有各自 window_id 和截图；不能按 PID
自动授权整个应用的全部窗口。新模态需要识别归属、纳入工作区并停止向被阻塞的
父窗口输入。当前只共享同 GUI 线程的 owned 窗口族 Hook；同线程独立兄弟窗口不能
同时接管，跨线程对话框的关系也不能按 PID 猜测。

`release_window` 不等于关闭应用或 Actor。释放前处理目标的输入状态并移除 Hook；
借用窗口按记录的有效原位置非激活归还，无法归还时保留明确的释放失败状态，不能
声称应用已关闭。`give_window` 和 release 都先把同线程受控窗口族从控制表移入
待交还表，清除输入路由和 state_id，再禁用 Hook、取消未开始的命令，等待已开始的
命令返回后卸载 Hook 并非激活移动窗口。等待超时返回 handoff_pending，保留禁用的
守卫和显示，允许 release 重试清理；旧 ID 不能再观察、输入、关闭或重新接管。
交还完成后只有重新发现得到的新 ID 才能显式接管。移动失败保留待交还状态。
共享虚拟屏由服务基础设施持有，独立库 `SharedDisplay` 的专用线程管理 IDD 句柄。
Windows Bundle 在驱动及 MSI 执行前，由非提权的缓存 CLI 通过 OS-owner IPC 正常停止
当前安装在账号 namespace 下默认及命名 profile 的运行中服务，等待进程与客户端退出，
释放显示设备及安装文件。启动锁覆盖服务初始化至控制端点发布，私有事务记录阻止
安装期间重新启动同一安装的服务。完成后按原监听地址、工作目录与 profile 恢复原来
运行的服务及客户端；不启动原本停止的 profile。MSI 回滚前再次停止已恢复的进程，
回滚完成后恢复旧安装；失败的准备步骤自行恢复。崩溃遗留记录不永久阻止启动，重试
安装保留此前已停止的服务参数。此协调不提权、不重放已开始的 App 效果，也不替代
Windows 对其他用户或外部进程持有设备句柄时的真实重启要求。
Windows 服务在本机 GUI 操作已启用时，于对外就绪及激活 Agent worker 之前显式创建屏幕并等待工作区布局稳定，
不等待首次工具调用；默认同一服务进程的全部 Actor/System 复用一个输出。
驱动不可用时记录启动诊断，其他服务功能继续工作；后续 ComputerUse 操作仍按实际
驱动状态返回错误，由 Owner 在 GUI 操作设置中重试；不将启动预热当成桌面操作授权。账号维护命令不创建屏幕。
设置页的 GUI 操作分类按服务能力显示 Windows ComputerUse 或 Android PhoneUse 内容；
macOS 原生客户端显示其辅助功能与屏幕录制授权面板。
Windows 通过 Owner HTTP `GET/PATCH /v1/device/computer-use` 读取及串行修改本机开关和
驱动支持的分辨率；沿用账号授权、可信 Origin 与请求头，不新增 WebView 业务命令。
偏好保存在服务 profile 的 `computer-use.json`，不复制到账号或写入 Actor 配置。
为保留已有行为，缺省启用且使用 1920×1080；关闭后服务启动不创建屏幕，工具不能启用它。
变更时阻止新输入，等待当前操作结束并逐个归还已接管窗口，撤销旧窗口/截图引用；
普通 Actor worker 继续运行，不重放 App 操作。关闭后移除屏幕；调整分辨率时在原输出上
重配，窗口归还失败则保留显示和清理守卫、关闭操作准入，Owner 可重试。显示调整及偏好
持久化均成功后才发布新偏好；持久化失败回滚到之前确认的显示状态，无法确认则继续拒绝操作。
独立库 `SharedDisplay::initialize()` 支持无窗口区域的显式初始化，重复调用不重配输出；
普通库构造仍不改显示拓扑，未显式初始化的调用方在首次分配区域时创建屏幕。
交还最后一个窗口、App shutdown、模型切换和 App 空闲回收不拔屏，不重新配置
分辨率/位置。App 仅 attach 借用工作区，窗口保留 `DisplayRegion` 直到交还完成。
服务持有者全部退出后，仍有窗口区域时继续保留屏幕；最后的持有者和区域释放后
才正常移除。若输入仍在执行，后台清理线程继续等待，不能提前暴露窗口。
Owner 关闭 GUI 操作、服务进程退出或驱动卸载仍会拔屏；本接口不是跨进程/profile 的常驻屏幕代理。
异常退出导致的窗口重排仍遵守 Windows 热拔除边界。窗口租约、待交还窗口或 Hook
阻止 App 空闲回收；服务持有的空屏不阻止。驱动/显示失效时，存在区域就拒绝重建；
所有区域释放后下次显式接管才允许恢复，旧图像、路由和输入效果不重放。

共享屏幕在 Windows 工作区（避开任务栏）内优先寻找空位；放不下时按有界偏移层叠，
不因其他窗口占用拒绝新增接管，不缩小已有窗口、不增屏、不调分辨率、不移动其他 Actor 的窗口。
区域是窗口放置/生命周期租约，可相互重叠，不能作为独占像素或输入授权。尺寸调整尽量保留原位置。
执行和观察检查窗口仍位于租用区域；旧/新区域在确认移动前均保留其租约。
首次创建等待 Explorer 的工作区布局稳定，避免任务栏稍后出现后压缩已分配区域。
截图使用指定 HWND 的 WGC 合成表面，被遮挡仍可观察，不混入覆盖窗口的桌面像素。
每次请求按需建立 free-threaded frame pool、取帧并关闭 session/pool；空闲不连续捕获。
DWM 扩展边框与 GetWindowRect 的差异以空白边框补齐，保持完整窗口物理像素坐标；
内容尺寸或窗口几何变化、未知表面尺寸、取帧/GPU 映射超时均拒绝发布，禁止整屏截图回退。
宿主串行化原生操作的准备、校验、输入和后续观察，以及设置关闭/交还的清理；推理不持锁。
Hook 命中从目标根 HWND 递归检查可见子窗口，不使用全局 WindowFromPoint；禁用控件或模态父窗拒绝。
UIA 从目标 HWND 的 RawView 子树按图像点命中，逐次验证真实 HWND/owned 关系，不按 PID 推断归属。
提供者把覆盖控件报告为 offscreen 时，可在操作前非激活提升该窗的普通 Z-order，再重新检查；
不设置 topmost、不恢复用户焦点、不在派发后切换后端或重放。原生 WM_POINTER 路径保留全局遮挡检查。

### 观察、坐标与输入目标

`get_window_state` 的语义结果包括 window_id、state_id、标题、实际图像 width/height、
完整窗口 window_width/window_height、相对完整窗口的 client_area、view.region/scale、
虚拟屏本地 workspace 尺寸和 window_x/window_y（不含系统绝对坐标）、
截图资源引用、input_target、related_windows 和 supported_actions。
默认截图包含完整窗口（标题栏、边框、客户区），原始分辨率；region 为完整窗口内的
像素矩形，scale 为 1..=4 的整数倍率，均为空时恢复默认。越界裁剪直接拒绝，不返回
残缺图像；图像至多 8 百万像素。弹窗单独标识，不让 Agent 估计系统坐标。
坐标以实际返回图片的左上角为原点，使用图片像素。App 保存裁剪/缩放、DPI、
客户区/屏幕/子控件变换，在执行时完成转换，不把 HWND 或显示坐标推给 Agent。
新观察撤销旧坐标；输入完成后的默认观察恢复完整窗口。非客户区可见但不能作为
鼠标输入接收面，标题栏管理使用 adjust_window。当前视口外的内容需要滚动或调整窗口，
截图放大不能显示应用没有渲染的文档内容。

`adjust_window` 的 resize 使用完整窗口尺寸，move 使用相对虚拟屏的 x/y；fit 选择
整个屏幕可用工作区，restore 恢复到现有保留区域，未使用参数必须为空。state_id 通常绑定
最新观察；无法截图时允许显式传空恢复。宿主保留新旧区域直到实际位置确认，移动
超时不释放任一可能区域、不自动重放。最大化窗口在既有激活守卫下还原再非激活移动；
接管最大化窗口也使用这条路径。不重建屏幕、不改变分辨率、不挪动其他窗口。
调整后清除接收目标并返回完整窗口观察；焦点、前台、捕获或光标变化停止输入，
不通过恢复用户桌面掩盖干扰。
原生放置只发送一次，随后有界等待目标几何稳定；不因系统或应用自行重排而反复移动。

首版以截图为主，不虚构可访问性树。UIA 以后可增加真实的 element_ref 和语义
操作；在实现前不发布 set_value、secondary_action 或伪造的元素索引。
截图通过现有 Actor Resource ledger 和工具 model_images 返回，进入模型视觉
内容；工具 payload 不塞 base64，客户端事件只传引用，展开时再读取重资源。
不支持视觉的模型收到明确能力错误，不能先执行动作再发现无法观察。

每次坐标/输入操作必须带对应窗口最近的 state_id。它绑定截图坐标变换和输入
代次，其他输入、重新接管或窗口/模态变化使旧引用失效。它不冻结应用，也不能
证明截图后像素未变化；执行前仍需检查身份、几何、命中控件和阻塞窗口。
普通异步动画不应因逐帧像素 hash 不一致而导致操作永远被拒绝。

每个输入工具完成后自动采集并返回新观察，Agent 看过新观察再决定下一步。
不提供盲目的多动作批处理；一个 drag 的完整轨迹仍算一个输入动作。
直线拖曳只需给起终两个点，中间移动由宿主采样；曲线任务给折线点，不能要求
模型机械计算插值。滚动量使用滚轮刻度，正 delta_y 向下、正 delta_x 向右；
宿主转换原生方向/单位，不承诺应用会移动精确的文档像素距离。
截图反映当时画面，不保证应用完成业务操作。等待加载时再次显式观察，不使用
模型轮询运行时全量快照或后台连续截图注入对话。

`input_target` 是 App 记录的明确派发目标，不是 Windows 前台焦点。
点击通过原生命中测试解析控件并更新此路由；派发文本/按键前重新校验它仍属于
接管窗口。观察会说明路由目标及其边界，但不会把“点击过某控件”等同于编辑器
已获得内部焦点。尚无有效输入目标时返回错误，不把文字发给用户当前编辑框。
App 以 HWND、控件类名和几何记录路由并执行校验；lib 接受明确控件 HWND。

`press_key` 使用可移植按键名称（如 Enter、Escape、Ctrl+A）；后端
明确报告实际支持范围。当前 lib 的 Shift/Control 消息派发不等于 accelerator
消息循环、Tab 导航或系统快捷键均已实现。未支持的按键、右/中键、水平滚动等
在作用前返回 unsupported，不能退化成用户桌面的 SendInput 或激活窗口。
不提供 `activate_window` 逃生通道。`type_text` 提交最终文本，不模拟拼音输入。
首版仅单次左键、纵向滚动、Shift/Control 组合及有限导航键，文本每次最多
1024 个 UTF-16 单元；拒绝 Tab、Alt、Win、双击、其他鼠标键及水平滚动。

### 结果、授权与集成边界

输入结果区分 not_started、dispatched 和 outcome_unknown，附派发回执、当前
观察或 observation_error。派发成功但截图失败属于未知结果；超时、取消、
重启或设备失联不自动重放输入。窗口应用卡住也可能阻塞它自身的 GUI 线程，
不能把库中的有界消息数量描述为任意应用都会按时返回。
窗口/观察引用属于创建它们的设备和宿主代次，不能随 Actor 迁移到另一台设备
后继续使用。恢复保留 Actor 历史和截图资源，重新发现实际窗口，不自动重启应用。

ComputerUse 采用一项粗粒度的设备桌面操作授权，沿用 Ask / Auto / Full access
及 Actor 的自动记忆，不按点击、打字、拖曳或应用分别建立审批权限。审查指纹
对应明确的设备桌面能力范围；不把每个坐标和文本内容变成新的动作级授权。
纯枚举沿用普通查询规则；首次接管/启动取得该能力，后续已覆盖操作复用授权。
桌面能力经明确授权后是项目文件沙箱的例外：任意宿主 GUI 可读取/修改该 Windows
用户能访问的文件，不能声称隔离了服务凭据或其他 Actor 的磁盘数据。此例外不修改
传给 Files、Terminal 或其他 App 的沙箱。设备 epoch、认证只读远端拒绝、DL 自身
进程/窗口排除仍逐次检查；截图资源继续由 Actor HTTP 授权保护。模型指令不替代隔离。

原生 Windows 打包包含版本匹配的 Hook DLL 和驱动部署包，普通 Cargo lib 构建
仍不自动调用 WDK。安装器负责正常提权的签名驱动部署/修复，模型不运行管理员
命令或管理证书。现有客户端 per-user MSI 与机器级驱动部署分别处理，不把
整个客户端悄悄改成管理员常驻程序。发行前仍需验证真实签名包、升级/回滚、
驱动稳定性及应用兼容性；本节不是对这些验证已经完成的声明。

显示拓扑配置的实测边界：创建/移除自有 IDD 屏幕时，Windows 可将系统光标重定位
到主屏中央，物理输出模式未变也可能发生。这不是 Hook 鼠标输入造成的移动；
App 不通过事后 SetCursorPos 掩盖此行为。目前不保证屏幕生命周期期间光标位置不变。
输入/WM_CLOSE 处理器若进入同步模态循环，会使命令保持执行中；超时后输入停止，
交还保持 pending，直到处理器退出。跨线程模态与任意应用兼容性尚未得到完整验证。

## PhoneUse App（Android）

Android 提供 `phone_use` 设备 App，普通 Actor 获得，Core 仍只直接持有 Actors。
Owner 在独立的「GUI 操作」设置页启用设备能力，并选择 Shizuku 或 Root。
Shizuku UserService 使用已授权的 ADB（UID 2000）身份；Root 使用
librootkotlinx 的 RootSession/RootCommand（UID 0）。Rust 服务、Files 和其他 App
仍在普通应用 UID 中运行，不获得 shell、任意 Binder 或 root 文件系统接口。
原生配置命令只接受可信主 WebView，并逐次检查当前 Owner 会话。
模型工具不能启用、重新连接或更换授权方式。进程重启、授权丢失或连接断开后，
由 Owner 在设置中重新连接；不自动请求系统权限或重放操作。

已验证的显示隔离策略要求 Android 15（API 35）以上；旧版本明确拒绝。
每个 Actor 持有独立的虚拟屏幕，默认 1280×720、160 dpi，启用独立焦点、
禁止抢占全局焦点、隐藏 IME 策略与随屏销毁任务的 flags，并检查实际显示标志、
display unique ID 和存活状态。普通窗口的发现、截图、触摸和按键仅限该屏幕。
不移动用户主屏任务，不接受模型提供的 display ID，不回退到主屏输入。
截图通过 ImageReader 获取，再以 FD 传给普通 UID；Rust 将其发布到既有
Actor 资源账本，客户端和模型沿用相同的授权资源契约。
GUI 操作的高级设置通过独立 Owner 原生命令串行保存设备本地的宽度、高度和 DPI。
宽高为 256–4096 的整数，单屏及存活屏幕总预算均不超过 800 万像素，DPI 为 80–640。
建屏及调整尺寸时核对系统实际尺寸和 DPI。高级设置先保留草稿，Owner 点击应用后
原地调整已有 VirtualDisplay 和图像接收器，不增加屏幕或重放任务；旧窗口和截图引用
全部撤销，需重新发现和观察。失败时回滚已调整屏幕；无法确认回滚则关闭操作准入，
由 Owner 重新连接。配置持久化失败同样回滚尺寸；仅在确认调整与持久化均成功后发布
新偏好。模型不能修改这些偏好或覆盖请求中的建屏参数，失败或校验失败保留界面草稿。

工具前缀是 `phone_use__`，沿用发现、接管、观察、操作、再观察流程。
launcher app_id、window_id 和 state_id 都是宿主生成的 opaque 引用。
启动前记录实际 task 集合，只有确认目标包在自有屏幕出现唯一新任务才返回成功；
应用拒绝多屏或复用已有任务时返回 outcome_unknown，不能盲目重新启动。
已知 singleTask / singleInstance launcher 在派发前拒绝。应用内部后续导航仍可能
调用系统单例路由；任意第三方应用的导航兼容性并无全局保证，目标身份变化后必须
重新发现，不能继续使用旧窗口引用。
输入前校验 Actor、执行代次、任务、无障碍窗口与根节点身份、几何、遮挡和最新观察。
取消在独立通道关闭未开始的操作；进行中的手势释放触点，未知效果不重放。
截图支持窗口内裁剪与 1–4 倍放大，输入坐标始终相对返回图像。

Android 不提供 Windows 的 adjust_window、give_window、type_text。
点击选择实际可编辑节点；`set_text` 通过 ACTION_SET_TEXT 替换完整 Unicode 文本，
返回控件实际文本，不模拟第二套输入法。自定义不支持此操作的控件明确失败。
按键只接受实际支持的有限导航键，触摸只支持单次左键、纵向滚动和有界拖曳。
release_window 撤销旧引用并保留任务，重新发现后需显式 open_window。
新虚拟屏显式设置并核对 DISPLAY_IME_POLICY_HIDE，禁止副屏编辑器连接或迁移主屏输入法；
文本输入走所选控件的 ACTION_SET_TEXT。close_window 移除选中任务，不调用 force-stop；Android 可在最后一个任务关闭后
异步回收缓存进程，关闭回执有界等待这次回收，避免立即重新启动时进入正在退出的进程。
普通 App detach 保留有任务的屏幕；
Owner 关闭连接或执行账号工作重置时释放屏幕及任务。无任务的 detach 回收空屏幕。

操作沿用 Actor 的 Ask / Auto / Full access 和权限记忆。粗粒度授权指纹包含
设备及实际授权方式、UID；切换权限来源后重新审查，不按每个坐标和文本重复授权。
只读远端拒绝、DL 自身应用排除与设备执行授权始终有效。
目标 GUI 应用保留其 Android 用户权限；本能力不声称为目标应用提供文件沙箱。

## 执行与恢复

SQLite 的事务同时提交消息变化和语义事件，稳定 ID 标识输入、工具调用、资源
和审批；全局事件游标单调递增。委派立即排队，结果关联原请求、原来源和交付
引用。入队时保存权限上限，接收者之后新增的权限不能被旧委派使用。
ActorStore 的同步数据库调用在多线程 Tokio 上使用阻塞边界：在等待数据库锁之前
交还 scheduler，直到查询或事务提交完成后才返回，避免读取、鉴权和 Raft 落盘
共同耗尽异步 worker。FULL 持久化、提交顺序和不可取消的同步事务语义保持不变；
单线程 runtime 与普通同步调用仍同步执行。慢访问只记录源码位置和耗时，不记录数据。

Actor 数据库使用 SQLite 自身的容量上限，不设置账号历史的固定 1 GiB 配额；
事件分页、单块文本和同步帧仍保持有界。模型进度的正文与思考事件只包含新增文本，
提供商在每次请求内分别记录已发送的 UTF-8 字节位置，结尾只补发未发送的尾段。
Anthropic 按通道缓冲实际增量；runner 合并增量后分块持久化，禁止把累计全文作为
增量重复追加。新请求和重试重新建立发送位置，草稿重置划分独立 generation。

核心使用同一个串行 inbox 和 Agent 循环，以短回合协调。Actors App 的 `deliver`
创建独立的 `delivery` 消息，其来源与收件人从当前输入构造，模型只能提供正文与
`finish_turn`。交付 ID 由 Actor、输入和调用 ID 确定，相同调用不会重复发送；
核心先保存交付记录并提交账号账本，再幂等发布消息事件和远端交付；未提交记录不进入会话查询，也不能作为恢复成功的凭据。`finish_turn=true` 在
整个工具协议组写完观察后关闭当前输入，无需再调用模型；不结束任何被委派工作。
已有显式交付时，最后的模型文字只关闭回合，避免重复用户消息。没有显式交付的
直接最终回答仍沿原收件人交付。普通 Actor 的 `report` 将重要进展关联原请求，
作为 `progress` 输入唤起请求方，而不修改执行中任务的状态。Core 自行选择汇报内容。

Core 的用户输入按 IM 消息立即持久化并返回，不等待当前输入执行完成。新用户消息
到达时丢弃尚在进行或重试等待中的旧模型请求；已开始的工具协议组先完整结算，
随后静默结束旧输入，以保留的历史和新输入继续推理。此切换不取消委派、回收 Actor
或重放已完成的 App 操作；每条新输入保留自己的身份与权限。协作者进度本身不抢占
推理。Core 输入框始终提供发送按钮，不显示终止任务按钮；普通 Actor 保留任务控制。

所有 Actor 的 Actors App 提供 `yield`：成功观察持久化、当前工具协议组完全结算后，
只关闭当前 inbox 输入，不生成最终正文、占位结果或远端交付，也不再请求模型。
它保留 Actor 身份、上下文和委派关联；后续协作者输入仍沿原请求唤醒并汇总。
`Completed` 表示该输入处理结束，不能据此断言其委派目标已全部完成。等待必要协作
时使用简短的重要进度和 `yield`；必要结果整合验证后才发送完整最终答复。
无新增事实的确认、重复发现及汇报后的常规回执静默处理，不发送“保持静默”等占位正文。

普通 Actor 的 WebUI 按助手正文划分活动组：跨模型轮次、仅夹有思考的连续工具
调用合并为一行摘要，展开后按原始调用顺序呈现，具体结果仍在点击对应调用时读取。
推理中的最新思考段落只临时替换当前活动组的单行标题，不提供完整思考正文的展开
入口；尚无工具时该标题不可展开，工具开始或推理结束后恢复活动摘要。
展开的活动记录保留已消费的事件前缀；实时窗口移过未消费记录或收起期间出现缺口时，
按消息活动游标增量补齐后再接续。工具摘要只补充已有调用的结果，不决定时间位置，
也不把未匹配摘要追加成末尾的独立汇总折叠。
已应用的引导消息按原发送时间插入所引导任务的活动流，作为正文和工具组之间的
用户输入边界，不统一移到原任务开头。活动分页未达到其时间位置时不提前显示；
收起活动时仍保留引导消息。Core 和搜索结果按消息自身顺序各显示一次。

模型执行不限制消息数、ReAct 轮数或工具批次数。输入预算包含消息、工具定义、
参数、观察和输出预留。完整协议组保持平衡；上下文满时清空工作窗口，插入
读取归档历史的恢复提示，不压缩、不滑动裁剪。`read_history`、`read_resource`
只读取自身 Actor 的原请求、指导、观察和资源；历史是证据，不能成为新授权。

窗口清空锚点与按模型绑定的 token 校准持久化。每次成功请求使用新鲜的实际
input usage 保守校准；低观测值不降低估算，缺失 usage 不复用旧观测。
Commentary、仅 reasoning 的继续响应和多工具协议保持完整。请求重试有退避与
取消检查；连续无内容响应的错误保护不构成正常任务轮数上限。

取消中断模型和工具等待，不承诺回滚已经发生的外部效果。重启记录中断状态；
不能在取消、重启或接管后自动重放不明确的 App 效果。诊断保存到 Actor 私有
目录，凭据经过脱敏，客户端只收到安全错误码。

用户输入执行中继续排队。修改、撤回与引导检查消息所属 Actor、用户来源、
当前状态和 `expected_updated_at_ms`，事务内拒绝过期操作。引导绑定确切的
运行请求；目标结束时未应用的指导恢复为普通输入。清空只处理尚未执行的用户输入。

## 账号与设备

账号身份来自持久信任根公钥的指纹，账号名是登录名；同名不是同一身份的证明。
`--profile` 隔离本机账号、Stage 身份、凭据、配置与 Actor 数据。

浏览器和 Rust 使用同一 `daat-locus-auth` 实现 OPAQUE，采用 Ristretto255 /
SHA-512 / TripleDH / Argon2id。密码留在客户端，没有 Owner Token、Bearer
认证入口、配对码或人工设备加入界面。首台设备注册和空设备身份安装必须验证
本地 OS 所有者连接；loopback、Origin、Host 或 Forwarded 不能代替此验证。

空设备登录会寻找在线账号设备，经 OPAQUE 双向验证取得加密加入记录。上下文
绑定账号、来源、目标设备、公钥/TLS 指纹/一次性证明、Origin 与连接边界；
LAN 使用 TLS exporter，公网交换使用本次 nonce。HKDF / AES-256-GCM 使用
单次登录密钥保护身份和私有注册记录。本机安装校验成员链、账号命名空间和
凭据修订，再完成本机登录。Apps 不可读取这些记录。
公网会合挑战的客户端预检容忍最多 30 秒时钟偏差；签名保留服务端给出的原始截止时间，
Worker 仍按自己的时钟、原始 nonce 和截止时间拒绝过期或重放请求。
设备加入请求和成员凭据在设备及 Worker 验证时允许最多 30 秒的未来签发偏差；
此容差不延长凭据有效期，也不放宽撤销、签名和授权链验证。

浏览器使用随机 HttpOnly / SameSite=Strict cookie，HTTPS 附加 Secure。
Cookie 绑定确切 profile、账号公钥命名空间和凭据修订；最长 12 小时。退出、
到期与已知撤销使会话失效，每次 HTTP 操作、SSE 输出与心跳重新验证。
登录或退出不会改变 Actor 生命周期。没有访客分享、PIN、公开隧道或分享会话。

账号设备自动发现、连接、同步与重连。LAN 使用 mDNS 和认证 TLS；SSH 需要
明确目标；可选 CF Worker/DO 仅提供公网会合和 P2P 信令。LAN、SSH 和直连
不依赖 CF。发现提示只能提供候选，不能授予信任。设备名默认使用系统 hostname API。
公网 WebSocket 在 Android 上使用 WebPKI 与 Mozilla 公共根证书验证证书链、域名和有效期，
避免 JVM 验证库将缺少 OCSP 响应地址误判为证书吊销；其他平台使用 OS 证书验证。
设备间 TLS 仍按设备身份固定证书指纹，两种信任边界独立。
公网连接交错尝试 DNS 返回的 IPv4/IPv6 地址，间隔 250 毫秒并竞速完整 TLS/WebSocket
握手；单个地址卡住不会耗尽其他地址的连接机会，成功后取消其余尝试。
公网在线提示只有在本地成员账本验证后才触发自动连接；初次连接不依赖模型已配置、
执行 worker 已取得租约或新设备已加入投票成员，避免连接与同步相互等待。
启用公网 WSS 连接后，P2P 默认通过 Cloudflare 与 Google STUN 获取 NAT 地址候选，
以同一个 UDP 套接字的两次目标观测识别映射是否变化；显式配置的 STUN 地址优先使用。
LAN/SSH 不依赖 STUN。P2P 协商与连接失败进入有界退避并保留
诊断原因，不因一次设备连接失败终止所有公网信令；直连受网络限制时仍可能无法建立。
ICE 收集最多等待 5 秒后签发当前候选集合，不能因某个接口的 STUN 无响应而丢弃已有
可用候选；没有候选时明确失败。候选仍通过原有签名 SDP、DTLS 指纹与设备握手验证。
收集已产生公网候选，或已确认对端支持增量候选时，允许在 300 毫秒后先交换 SDP。
增量能力通过签名 SDP 声明；后续候选沿用现有签名信令，在最多 20 秒的窗口内合并发送，
不需要 Worker 新增协议。接收方只接受同一 source/target、代次、nonce、SDP 类型、
DTLS 指纹、ICE 凭据和其他固定 SDP 字段，最多累积 32 个候选，不能重新设置远端 SDP。
无此能力的对端不接收更新；没有可用公网候选时，初始 offer 保留原收集等待上限。
支持增量协商的两端还需通过签名更新确认双方 DataChannel 已打开，再进入身份与代次
确认；仅本端的 Open 事件不能证明对端已能接收首帧。此就绪通知只属于传输协商，
不代表执行租约、授权或业务提交。
ICE 检查覆盖收集与连接等待窗口，不能在约 1.6 秒后停止探测再空等外层超时。
双方通过签名 SDP 的可选扩展声明已观测的公网 IPv4 与映射行为；只有一端映射稳定、
另一端映射变化时启用增强打洞。每台设备最多同时执行两次，单次最多 12 秒：变化侧
最多创建 128 个临时 UDP 套接字，稳定侧最多尝试 2048 个端口，先探测观测端口附近，
再随机探测。目标 IP 必须来自该对端签名 SDP 中已有的公网反射候选，不扩大到其他
地址或特权端口。观测不足、旧客户端或双方映射均变化时保持普通 ICE。
套接字池按 16、64、128 分阶段扩展，邻近端口优先快速尝试，再平滑使用剩余随机预算；
调度延迟不能造成追赶式探测突发。正常 IPv6 ICE 与交错的 IPv6/IPv4 LAN 候选优先参与竞速。
首个完整性校验成功且凭据匹配当前协商的 ICE 回应锁定物理套接字，立即停止增强探测；
超时、连接完成或关闭均释放其余临时套接字。DTLS、SCTP、后续业务与保活继续复用实际
打通的套接字，不通过重新绑定端口迁移，也不重放业务操作。Worker 仍只传递认证信令。
公网同步信令注册总等待不超过 10 秒，发送不超过 5 秒；每 15 秒主动发送带随机
nonce 的 WebSocket Ping，只接受匹配 Pong，30 秒未确认则关闭并重新注册。登录发布
连接和同步信令分别验证存活；业务同步仍只走认证的设备直连。LAN 失败转交公网
协商时先释放 LAN 的连接中状态，由公网尝试负责失败退避，不能提前将其设为退避。
监督器先注册唤醒再读取候选，避免新设备加入或信令恢复时丢失连接通知。私密登录
导入后立即保存已验证来源的名称并请求连接；对端名称随后经认证通道传播。未知
名称显示为未命名设备及 ID 前缀；设备列表仅返回固定连接错误码，不公开底层诊断。
RTC 协商签名采用 90 秒有效期，在验证端 120 秒未来上限内预留 30 秒时钟偏差空间；
过期、来源、目标、nonce、连接代数和 DTLS 指纹检查保持强制。
`workers/signaling` 是独立的可选部署单元，不是 quick-tunnel 子模块。

模型、提供商定义和可移植凭据在同账号内私密同步，拒绝回滚和同修订不同内容。
环境变量实际值、OAuth 文件路径、监听地址、公网连接地址和 SSH 目标保持
设备本地；语言、外观、草稿与展开状态是客户端偏好。配置页固定显示本机和账号设备
的名称及连接状态，使用有界分页自动刷新，不提供手动加入设备控件。离线设备在恢复连接后
补齐修订，无法即时获知离线期间的撤销。

## 共享账号 Actor

账号的默认入口为 `core` Actor。其身份、收件箱、模型上下文和对话属于账号，
不属于某一设备；设备提供 App 实例并临时承载 worker。普通 Actor 仍有宿主。
Core 是唯一预置 Actor。普通 Actor 由创建它的 Actor 命名，通过 Actors App
创建，不自动生成设备 root 或默认执行 Actor。设备默认工作区与能力约束属于
基础设施，不以 Actor 身份保存。既有本地 root 的身份和历史保留为普通 Actor，
不再具有特殊路由或权限，也不靠合并独立 root 来模拟共享 Actor。

核心直接工具固定为一个便携 Actors App：设备发现、分页 Actor 列表、创建、委派、
请求状态与取消，以及自身历史、资源和对话交付。模型使用明确的 `stage_id` 指定
普通 Actor 的宿主；原生 Core Invoke 仅允许 Actors 协作操作，不能转调 Files、
Terminal 或 Browser。构建模型工具不依赖逐设备网络目录查询；实际操作时重新检查
目标设备的目录修订、执行代际、权限与审批。读取操作目录先验证 worker 代际并同步
已提交的账号状态，再计算目录修订，避免执行前同步配置使刚读取的修订失效。
执行时仍重新校验修订，拒绝其间真实发生的权限变更。设备离线时不更换操作目标。

同设备的非 Core Actor 安装全量平台 App 与启用的 MCP App，创建工具不接受
`apps` 或只读身份。Core 只构造跨平台 Actors App，不安装其他 App，也不使用能力
白名单。`app_access`、工具白名单、委派 App 上限、本地只读身份和收件人列表均已
移除。普通 Actor 通过自己的项目沙箱和审批记忆执行；所有项目工作目录默认递归
可读写。项目 AGENTS 和 Skills 由普通 Actor 读取，不自动注入 Core 的模型上下文。
远端设备认证与只读授权仍在执行期独立校验，委派和审批记忆不能扩大远端授权。

```mermaid
flowchart TB
    UI[WebUI] --> Core[账号 Actor]
    Core --> Devices[认证设备通道]
    Devices --> A[设备 A：App 与临时 worker]
    Devices --> B[设备 B：App 与普通 Actor]
    A <--> B
    Relay[可选 CF 会合与信令] -.-> Devices
```

执行协调属于账号设备。OpenRaft 持久化投票、日志、快照与联合成员变更，确认
执行代际、租约和共享提交头，正文走认证设备通道。新账号初始化一个授权节点，
后续设备为 learner；旧的多投票者成员通过原有 quorum 收束。同步副本不增加
日常运行的永久投票依赖。成员维护在独立循环中使用截止时间，不阻塞 worker 续租。
正常退出暂停并同步当前执行，再通过联合成员变更把授权节点交给已同步设备。
健康且可执行的 worker 保持亲和；不再具备执行条件时释放租约。状态查询返回后
重新读取本机提交头，不能因并发检查点让旧查询结果撤销健康 worker。输入就绪
门禁与已开始推理、工具调用及显式消息交付的执行权限分离；短暂同步未就绪不能撤销
仍有效的执行授权，后者仍严格检查租约、代际、暂停和退出。worker 完全
停止后，残留的运行中输入必须先恢复推理与不完整工具协议，再开放串行 inbox；
Actor 的暂时空闲状态不能绕过运行中输入。

异常失联时，已同步、授权和模型配置有效的设备无法取得账号仲裁确认时，在既有授权
失效后进入持久的本地恢复分支。副本之间仍在线不代表仲裁可用。分支有独立标识、
起始提交头和递增代际，不改写 Raft 投票者，也不宣称取得多数提交。个人账号选择
可用性优先，因此网络分区中各侧可能分别推理。
重连后，由现有账号授权节点暂停各侧执行，按检查点序号降序、StageID 升序选择
完整的推理上下文；后返回的旧代际分支仍参与恢复。替换前把原分支保存在同一个
私有数据库中，按分支分别映射消息和操作引用，把用户消息、完成结果与只读操作
记录自动合并到活动对话。相同输入的不同结果使用稳定标识保留，合并可重复执行；
不拼接有分叉的模型工具协议、不导入待批准操作。旧版尚未合并的归档也通过有界
原生分页自动补回。共享头由原有 quorum 确认后恢复执行并标记归档已合并；同步
期间续期暂停状态。未开始的输入保留约束并继续交付；其他分支中已开始或结果未知
的工作只保留已取消记录，不自动重放。客户端直接呈现合并后的正常对话，不提供
额外的恢复历史按钮。配置就绪查询读取当前生效配置；共享 Core 的模型定义就绪
与本机凭据可执行性分开，账号配置修订触发客户端模型列表刷新。
重启不恢复缓存租约，本地分支代际也递增。CF 不拥有租约、代际或业务提交权。

LAN 地址候选有过期时间并处理服务撤销，最多四路同时验证 TCP/TLS，整次拨号
有截止时间。LAN 探测 300 毫秒仍未完成时并行准备公网直连，显式 SSH 不参与竞速。
TCP/TLS 和 ICE/DTLS/SCTP 的准备不占用设备提交锁；稳定排序选出的拨号方选择先就绪
路径，另一端先等待该路径的签名 Hello，再获取提交锁。代次确认仍严格串行，失败或
落后的候选不能替换健康连接，也不能让两端在不同路径上互相等待。
系统接口地址变化和 Android 回到前台会唤醒重连、清除旧 LAN 候选与失败退避，
重新注册公网信令及登录发布；健康业务连接只探活，不直接拆除。旧网络协商不得发布新连接。
LAN 拨号、候选收集及 ICE/DTLS/SCTP 建链记录分阶段耗时和成功状态，内容完成记录字节与耗时；
传输指标分别记录内容原始字节和线上协议字节，不包含凭据、SDP 或消息正文。
失败记录原因、安排重试并唤醒调度，新发现可打断退避。连接静默判定为六秒，
写入也有截止时间；WebRTC 关闭和失败直接结束通道，短暂的 ICE
Disconnected 允许自行恢复，不能提前销毁仍可恢复的连接；失联仍受业务心跳截止时间约束。
内容传输按每个资源最多 8 个在途分块、每连接最多 24 个内容请求进行有界流水线调度，
为控制 RPC 保留预算；块可乱序到达，仍逐块及整体校验 SHA256，并复用已持久化的分块。
原生 TLS 通过 ALPN `daat-locus-stage/2`、P2P 通过签名 SDP 协商二进制内容帧；
旧端保持 JSON/Base64。新版内容帧保留 JSON 元数据、原始二进制分块，对可压缩 UTF-8
文本使用 zstd；只有节省空间时才压缩，解码严格限制帧、解压后分块和 zstd 窗口大小。
P2P 内容与控制分别由独立发送任务处理，仍共享总字节预算；容量等待结束后、实际发送前
逐帧复核授权，不能复用进入等待前的授权结果。
通道记录第一个读、队列、容量、鉴权或写入失败及其错误链；关闭通知和最终连接诊断
使用同一原因，后续 EOF/清理不能覆盖它，也不输出帧内容或私密凭据。
内容背压等待容量而不直接断链；原生流仍共用物理流，不宣称消除了 TCP/SCTP 层队头阻塞。
公网 ICE 协商
在独立任务中进行，在线通知与心跳保持可处理。客户端区分连接、同步、恢复、
本地运行及恢复阻塞。等待使用原有居中环形加载与模糊遮罩，保持消息和草稿组件
挂载，暂时禁止对话交互；可用的本地恢复不额外显示提示条。完成分支合并后从
语义事件重新读取有界对话页面。

工具意图先复制提交，目标设备再检查代际、授权、审批和 sandbox。工具结果和
最终回复进入持久账本；可读取已确认结果，不重放 Unknown 效果。原 App 设备
离线不能把文件或终端操作静默改投另一设备。输入使用已提交逻辑顺序，检查点
保留窗口锚点、token 校准、上下文和资源引用，接管不重新填充已清空的窗口。

## 权限与资源

Auto 的独立模型请求无 worker 历史和执行工具，只能 approve/deny；超时、
错误和无效响应拒绝，不转人工。未指定审查模型时跟随账号主模型；沿用所选模型的
响应与流空闲超时，不附加固定 30 秒截止时间。默认流空闲超时仍为 900 秒，显式设置
不被默认值抬高。Ask 等待 Owner 审批不可修改的参数与请求范围。
App 通过 `review_requirement` 声明哪些操作需要审查、审查标准以及语义动作。
默认普通操作不审查；超出沙箱的读写范围独立触发审查，不依赖工具名。
Full access 省去审查并使用本次请求的额外文件范围。Ask/Auto 的正向决定通过
`ApprovalFingerprint` 写入 `actor_approval_scopes`，按 Actor 和本地设备隔离，
重启后保留。目录授权递归覆盖后代，写授权包含读权限；更宽范围合并已经覆盖的
较窄范围，不自动扩大到父目录、同级路径或写权限。文件授权只覆盖该文件。
App 指纹绑定命名空间、审查标准修订和有意义的目标/参数；协议调用 ID、等待时长
等无关参数不产生新授权。App 安装修订或审查标准改变后重新审查。旧单次批准不
自动转为长期授权。拒绝、取消及失败审查不写入记忆；清理 Actor 数据时通过外键
同步回收，不增加单个 Actor 删除接口。记忆独立于 Actor 配置，不跨 Actor 继承。
批准后自动记忆，不提供记忆开关或额外提示。只有手动审批显示操作、请求范围与
确认控件；自动审批不显示审批卡片。
远端认证范围、框架凭据和其他 Actor 私有数据不能被批准或记忆绕过；已批准路径
被替换成指向其他位置的符号链接时，不将旧批准重新绑定到新目标。
取消、停止和重配置使等待审批失效，未确认的外部效果仍不得重放。

文件操作在实际打开目标时验证策略，不依赖提前 canonicalize 后的字符串检查；
写入用 SHA256 版本校验。受限原生进程隔离不可用时必须拒绝，不能退回宿主执行。
Windows 原生进程使用微软 MXC SDK 的 PSEC 后端，启动前探测实际可用性及 deny-path
能力；无宿主 ACL 修改、递归文件扫描、AppContainer ACL 兼容后端或宿主执行回退。
授权目录直接映射为内核读写根，只读例外和私有拒绝路径独立保留；卷根仅枚举第一层
以适配 PSEC 的卷根语义，不遍历目录树。已批准根的绑定检查仍然生效。系统运行目录
来自 Windows API，工作目录规范化以兼容 8.3 别名；过滤环境凭据，并将 SDK 依赖的系统目录变量绑定到 OS 查询结果。
PSEC 保留 AppContainer token 身份，现有本机 Owner/维护通道继续拒绝沙箱进程。
SDK 持有 Job 与隔离策略直到进程树结束；有界异步管道支持 Terminal/MCP 的流式收发，
进程句柄释放后，已产生且尚未读取的输出仍可排空。
Linux 使用 bwrap 的用户、PID、IPC、UTS namespace、能力清理和禁止嵌套 user namespace。
有限读取策略包含 Shell、动态库及最小系统配置，并在私有 namespace 提供 `/tmp`。所有授权绑定挂载之后创建私有
`/dev` 和对应 PID namespace 的 `/proc`，再应用只读例外与拒绝规则；祖先拒读遮罩
直接覆盖后代，不再重开嵌套路径。bwrap 在完成隔离后加载 seccomp；禁止 io_uring、
AF_VSOCK、按句柄打开文件及其他绕过隔离的内核接口，保留普通 IP 网络。
不存在的保护路径使用第一个缺失分量的空挂载点，不默许将来创建；只处理策略边界，
不扫描工作区。挂载点在同服务的并发沙箱间共享，直到最后一个 PID namespace 结束
才按 inode 检查清理；宿主写入的内容予以保留。跨服务占用冲突明确拒绝。
Linux 本机 HTTP 初始化权限同时核对 socket inode 所属进程的 user namespace，
不能将隔离进程的相同 UID 当成 OS-owner。维护 Unix socket 目录对所有 Actor 文件授权
均为私有路径；macOS 额外显式禁止连接此目录中的 socket，即使模型获批宽泛文件根。
启动门闩在 pidfd 取得后释放，取消先终止命名空间；Linux 需要支持 pidfd/openat2 的
内核和支持所用参数的 bwrap，不满足时拒绝运行。可写符号链接上的保护路径拒绝启动。
macOS 使用参数化 Seatbelt 策略，路径经 `-D` 传递，不插入 SBPL 文本；系统运行、TLS
及受限系统服务基线参考 Codex。拒绝规则覆盖 literal 和 subpath、缺失路径、祖先
目录改名与私有 Unix socket，并封闭只读描述符上的危险 fcntl。子进程继承策略，
取消及根进程退出时清理进程组；Seatbelt 策略不依赖父进程存活。
原生沙箱不可用时，Auto 和 Required 都不能将受限策略降级为宿主执行。
Chat 兼容流收到 finish_reason 后只短暂收取尾部用量，
不依赖 [DONE] 或连接关闭才交回执行权。重连活动视图从 tool_started 恢复未完成调用，
进入工具阶段后不再把前一段推理标为正在思考。
只读 Browser 使用有界 HTTP GET，验证 DNS、重定向与地址目标，不运行 Chrome /
页面 JavaScript、不继承环境凭据。私有存储写入前建立 OS-owner 权限并传播失败。

`src/resources.rs` 为本地与多设备使用统一资源描述：稳定 ID、版本、媒体类型、
哈希、长度和内容块引用，跨设备不传本地路径。资源通过所属 Actor 账本授权、
打开路径检查和哈希验证后读取。工具图片先捕获为持久资源，仅模型请求临时
解析成图片内容；模型接口不会重新打开未经验证的路径。完整输出同样归档为
资源，按 UTF-8 字节分页，保留原始内容。多设备 App 结果转交资源描述和内容块。

内部资源引用统一使用不透明资源 ID 或 `/v1/actors/{actor}/resources/{id}` URI，
不是本地文件路径或公开 HTTP 地址。引用只定位资源，不授予访问权限；统一解析器
核对当前 Actor 的账本，拒绝其他 Actor、路径穿越、查询参数或伪造存储位置。
所有 App 的模型图片经过同一捕获边界，返回 `resource_references`（ID、URI、名称与
媒体类型）并关联当前输入；原始文件路径和缓存路径不成为模型的资源访问方式。
图片可直接使用该 URI 在 Markdown 中引用，也可通过 Artifacts 的 `resource` 输入
交付，或通过 Actors.read_resource 读取；文本与完整工具输出使用同一引用体系。
Artifacts 的 `path` 仍处理有读取权限的本地图片/SVG/HTML，发布为不可变快照；
内部资源直接读取经过完整性验证的账本字节，不借用 GUI 权限扩大文件系统范围。

浏览器上传只提交资源 ID；服务端构造来源、回复与权限元数据。下载执行 Actor
授权与账本路径检查，HTML/SVG 使用无 same-origin 权限的 sandbox CSP。
签名与链接不能替代授权，凭据不能进入观察、同步公开内容或客户端诊断。

公网登录发布与 Core 执行独立。注册握手总时限 10 秒，发送时限 5 秒；
发布连接每 15 秒发送带随机标识的 WebSocket Ping，仅匹配的 Pong 确认保活，
30 秒未确认即关闭失活通道，按有界退避自动重新注册。网络变化、账号凭据变化
和公网地址修改唤醒重查，不复用旧注册状态。注册失败与 TLS、协议、授权、
心跳超时分别记录固定错误码；不记录账号私密材料或底层响应原文。
设置页显示实际公网登录状态，地址已保存不代表注册成功；状态查询失败显示未知。
这些状态是本机易失诊断事实，不进入 Actor 业务日志、模型上下文或复制账本。

登录失败使用固定的 `login_*` 错误码和不含凭据的短原因。发现层区分未配置
公网连接、公网服务不可达、未找到在线设备、设备连接失败和超时；认证层区分
账号或密码错误、尝试过期、设备撤销、凭据变化以及无法验证登录/加入信息。
账号名不存在与密码错误保持相同认证结果。HTTP 与原生账号桥保留相同错误码；
WebUI 根据中英文目录显示简短提示和可反馈的错误码，不显示底层诊断原文。
拒绝密码证明后只在候选耗尽时显示凭据错误，不能把后续网络失败改写为密码错误。

模型请求失败将固定错误码写入消息，底层 HTTP/TLS 原因、地址、请求计数和 token
预算只保存在受 OS Owner 权限保护且脱敏的诊断文件中。认证拒绝与证书吊销/验证
失败分别分类，永久失败不自动重试，也不降低证书验证。客户端只显示简短本地化
原因；旧消息的诊断原文不作为对话错误提示展示。共享 Core 消息由同一复制流传输，
不能再通过设备限定的普通 Actor 通知创建重复身份。

## MCP 与设备应用

标准 MCP 服务器使用官方 rmcp 客户端，安装后成为独立 App 实例；支持 Streamable
HTTP 和本机 stdio，Android 仅提供 HTTP。HTTP 使用独立客户端、不带浏览器 cookie、
禁止重定向；远端要求 HTTPS，本机环回地址允许 HTTP。stdio 使用 Actor 执行时的
强制进程沙箱、目录和受保护环境策略；预检结束、取消及 App 关闭会回收子进程。
安装记录与连接凭据原子写入 profile 私有 `apps.json`，不进入账号共享配置或观察。
公开查询省略令牌、环境变量、命令参数及 URL 查询串。

普通 Actor 安装 AppsManager；`list`、`inspect`、`refresh` 不声明动作审查。
`install`、`enable`、`close` 自行声明审查标准，指纹绑定实际连接、命令或安装修订。
MCP 适配 App 对远端调用声明审查，不把远端工具描述或只读提示当作授权。
停用立即拒绝新调用，已开始的调用允许完成。Core 继续仅构造 Actors App。

每个输入开始前对照目录修订；显式刷新在当前工具协议组的全部结果落盘后生效。
保留未变实例和资源，仅替换修订改变的 MCP 实例，不重启 Actor、不清空上下文、
不重放输入或外部效果。服务器工具变更通知在下一边界重新发现，发现变更后旧定义
不能执行。MCP 超时、断线和会话过期不自动重试工具调用。

保留服务器原始工具名和 JSON Schema。可移植 schema 直接暴露；其他 schema
通过可移植 `arguments_json` 对象封装，模型可用 inspect 读取原 schema，DL 在
审批和调用前校验解码值。缺省、null 和动态键保持原意。映射名包含稳定摘要，带
设备前缀后仍满足供应商的 64 字符限制。文本及结构化结果保留原文与类型；嵌入
资源进入 Actor 的授权资源账本，远端 `isError` 写入工具失败状态。

Owner 通过 `/v1/apps` 的有界搜索列表及安装接口、`/v1/apps/{id}` 的详情与单个
工具 schema 查询、`/v1/apps/{id}/state` 的修订保护启停管理本机应用。写操作检查
受信 Origin 与请求头。共享 WebUI 的 `/apps` 使用窄导航入口、无边框列表与连接
弹窗，不提供不存在的市场、OAuth、隧道或每个 App 的工作区页面。

## HTTP 与 WebUI

`src/service` 提供有界 Actor、消息、搜索、队列、工具结果、审批、资源、
配置和账号查询；`/v1/stages/{stage}/actors/{actor}` 经认证设备通道访问宿主。
对话链接只是定位符，Owner 可以直接访问任意 Actor。Cookie 写操作要求受信
Origin 和 `X-Daat-Request: 1`，不信任 Host/Forwarded，不使用宽泛 CORS。
账号 Core 启动时，将本机 root/Core 的既有 Actor 树补齐到已验证账号；已记录的
其他账号归属及其子树不被覆盖。新 Actor 继承父级归属，同账号设备无需逐个授权
即可访问。派遣结果的对话链接携带宿主设备 ID，旧 Core 结果通过原始设备参数
恢复定位。远端对话的模型就绪状态由宿主提供，客户端本机配置不阻止远端输入。

`/v1/stage/status` 仅返回当前 Core 同步、执行就绪与公网登录发布状态，每次查询重新认证。
WebUI 串行查询该小型状态；同步完成且存在有效 worker 时才开放 Core 输入，
并在同步完成后刷新模型选项。模型定义未就绪时，即使仍持有本地执行租约也报告
`model_required`，不把模型配置缺失呈现为连接等待；实际恢复阻塞和对账状态仍优先。
保存配置只刷新模型选项和 Actor 详情，保留当前对话消息、分页与 SSE 游标和订阅。
执行未就绪只限制发送，不遮挡历史记录、搜索、草稿编辑和设置；状态查询失败报告
执行状态暂不可用，不能把本机初始化或未知状态兜底成远端设备“连接中”。等待原因
在输入区显示静态状态，不使用覆盖对话的加载条。SSE 重连只影响观察更新，不单独
禁止发送。WebUI 回到前台立即刷新就绪状态，并取消后台遗留的 SSE 请求或读取，
按最后已消费的游标续接，保留消费者背压与未消费事件，不重载整段对话。
Android 前台恢复先解除本地执行暂停，再尝试恢复设备传输；传输启动失败记录原因，
不跳过本地恢复，Core 执行仍服从原有租约、同步与代际检查。
服务端对未就绪的 Core 发送返回 `503 core_not_ready`，
客户端保留草稿；已经接收的持久输入不丢弃。设备连接失败即显示离线，重试时间
独立保留；收到对端数据的等待超过 45 秒（3 个心跳周期）关闭失效通道。

`/v1/event-stream` 和 Actor 的 `event-stream` 发送小型语义事实与引用。
客户端从最后已消费游标恢复 SSE，先等待消费者接收事件再推进游标；注册唤醒
早于查询，每次输出与心跳重新认证，尊重背压。同步缺口触发有界重查；重连
不会反复传完整 runtime snapshot。工具正文和重资源仅在展开时获取。

Core 固定采用 IM，只显示明确用户交付、任务链接、决策与成果。其他 Actor
固定采用工作呈现，在桌面对话框和手机全屏中均使用同一种身份样式：普通正文、静默耗时
展开、细分活动与独立成果。活动按时间穿插在对话中，不使用嵌套滚动框。工具
参数用只读标记字段呈现；不以原始 JSON 或模型协议作为产品兜底。活动历史与
工具列表在展开且滚动接近分页边界时自动加载下一页；折叠后停止续页，加载失败
才显示重试操作，不提供“更多活动”分页按钮。

主窗口固定显示 Core。Actor 链接在桌面打开对话框，窄屏自动铺满视口，
左上返回上一层对话或主会话；会话不提供最大化切换。
进入 Actor 时直接查询最新一页并从底部原点显示，不先定位到任务的原始请求，
也不顺序加载旧页后再滚到底部。任务引用保留请求标识以显示状态；历史刻度导航
才定位指定消息。补载旧历史保留当前可见消息的位置。
搜索使用非模态悬浮栏，宽屏位于右上，窄屏位于上部居中；按有界查询过滤原消息流，
向上滚动继续加载较早的匹配项，不显示遮罩或独立结果目录。普通 Actor 在搜索期间
隐藏中间思考与工具活动，只保留实际对话；关闭搜索恢复此前阅读位置和完整活动。

主页面使用 52px 应用导航轨，手机使用模态导航侧拉栏，仅提供首页和账号/设置入口。
DL 只有一个 Core 主入口，不提供会话列表、“最近聊天”或常驻 Actor 目录。
搜索浮动在主内容右上角；主对话不显示固定品牌大标题或历史消息刻度导航。
Actor 引用仍打开对话框。非 Core 对话在足够宽的容器中提供本地已加载历史的
刻度跳转；按正文和输入框的实际留白显隐，空间接近不足时淡出，避免重叠，
全宽阅读同样适用，隐藏时关闭预览。刻度不占用消息区宽度。默认等长短条，深灰标记可见
消息范围；悬停或键盘聚焦只把目标条标黑，附近刻度逐级伸长，并预览该条
消息的原始请求及回复。密集刻度保持稳定的连续分组，不随滚动替换目标。
设置使用 `/settings/*` 整页分类和窄屏列表/详情导航，复用行、组、选单
和二级页面；常规设置语言，外观提供系统/浅色/深色预览、分模式的强调色/背景/前景和代码主题，以及界面/内容/代码字号、减少动态效果与全宽阅读。外观偏好只保存在当前客户端，立即应用于主窗口和 Actor 弹窗；旧偏好自动补齐默认值，配色校验保证文字可读，并提供恢复默认。提供商/模型编辑明确保存，其他设置串行窄 PATCH
自动保存。失败输入与待发送草稿保留。排队消息位于圆角输入框上方，附带附件、
修改、撤回和引导入口。模型与批准模式是输入偏好，不是 Actor 管理面板。

WebUI 文案维护在 `webui/src/locales/{zh-CN,en-US}.json`，使用 i18next /
react-i18next；默认选浏览器首个受支持语言，其他语言回退英文。常规设置可选择
跟随浏览器、中文、英文，自动保存并即时刷新。用户消息、文件与命令原文不翻译。

WebUI 与共享认证 WASM 独立构建到同一 `webui/dist`，Rust 构建脚本只消费产物。
Tauri 通过 frontendDist、本地资源协议与框架内置压缩提供原生页面；配套后台和
Android 核心关闭 embedded-webui，避免同一安装包重复携带资源。独立网页服务默认
启用 embedded-webui，按文件以 zstd 压缩嵌入，HTTP 按请求有界解压并返回原始字节；
HEAD 直接返回原始长度。无头服务关闭默认 feature，显式 `DAAT_LOCUS_BUILD_WEBUI=0`
仍可用于后台检查。模型目录以 zstd 嵌入，仅在首次需要编译时回退时流式解压解析，
优先使用已验证的运行时缓存，不保留一份完整解压文本。静态资源只来自编译时清单，
SPA 只匹配确切对话路径，未知 API 不返回 index.html。维护 CLI 用 clap 提前
解析参数；`serve` 前台运行，`start/status/stop/restart` 通过 profile 本地
OS-owner IPC 管理后台进程，不借用浏览器认证、不删除 Actor 数据。后台存活按 PID 与
进程启动时间识别，不依赖安装升级时可能被移动的映像路径；IPC 仍校验 OS Owner、
端点进程与实例身份。服务启动前捕获自身 EXE 的 SHA256，保存在本机维护状态中；
`start`（包括桌面客户端启动）只复用同一安装位置且指纹一致的运行实例。旧版本缺失
指纹或同版本重新构建后指纹变化时，通过原有 OS-owner 通道正常停止，再沿用 profile、
监听地址和 workspace 启动新代码，避免旧服务加载升级后的 Hook DLL。其他安装位置
的服务不能被这个自动升级路径停止。`status` 不触发升级，退出客户端仍保留服务。


Windows/macOS 的共用 Tauri 客户端位于 `clients/app/src-tauri`。窗口从配套 CLI
的 OS-owner IPC 状态取得并核对 profile、可执行文件与确切 loopback origin，
加载本地共享 WebUI，以受限原生传输复用后台 HTTP 查询和 SSE，不复制业务接口。
会话 cookie 保存在 profile 的 WebView cookie 存储，原生代码读写 HttpOnly cookie；
Android 使用系统 CookieManager。JS 无权选择服务 origin、注入 Cookie/Origin 或读取
Set-Cookie。上传和响应的 IPC 块均有界，避免 Android 的 JSON 二进制回退放大内存；
读块由消费者推进，取消会关闭请求，页面重载或后台 origin 变化使旧请求失效。
WebView 不授予 JavaScript 文件、进程或 shell 能力；外部链接打开系统浏览器，
授权资源经只允许 GET/HEAD 的 dl-resource 本地协议读取，仅接受 Actor 资源路径，
保持服务端逐块授权检查、响应大小上限和 HTML/SVG sandbox CSP，在无同源权限的
对话框中预览；该协议不代理其他 API，不向活动资源暴露会话或原生命令。
下载由 Rust 调用系统保存对话框（Android SAF），仅写入用户选择的目标；JS 只提交
已授权资源路径及建议名称，不接收目标路径，也没有通用文件系统/对话框权限。
Windows 和 macOS 14+ 使用 profile 独立 WebView 存储；更早 macOS 仍由服务端的
profile 与账号凭据版本绑定保证会话权限。

首次注册与未登录设备的账号接入使用有限的原生命令，经本机 OS-owner IPC 到同一
认证处理逻辑。原生权限只授予该 profile 的主窗口及本地应用页面，
资源预览无权调用。IPC 只处理未建立账号的 bootstrap，不能创建浏览器会话或修改已有
账号；普通 OPAQUE 登录仍由 HTTP 写入 HttpOnly cookie。公开 HTTP 不接受 native
标记、额外 Owner token 或仅凭 loopback 的注册权限。

客户端拥有原生窗口、托盘与主线程事件循环，后台不依赖 GUI。关窗仅隐藏，
退出客户端保留后台，服务维护通过 CLI 请求正常关闭。Windows 托盘仅提供
隐藏/打开窗口与退出客户端，使用支持键盘操作的原生大行距菜单。重复启动恢复
同一 profile 的窗口；后台重启后重连已核实的本机服务。CLI 与可选浏览器入口保留。
Android 将同一服务与 Actor/App 核心编译为 APK 内的 Rust 原生库，使用 OS 私有目录，
不启动桌面 daemon、CLI 子进程或独立 root。它可以创建账号并独立推理，也可以成为
同账号共享核心的执行设备。设备可为普通 Actor 提供 Actors、Files、HTTP Browser、Artifacts、PhoneUse；账号 Core 直接仅用 Actors；
终端不安装，未实现的进程隔离始终拒绝。Files 使用目录句柄与实际打开 FD 校验，
Android 上以 O_PATH 遍历不可列举的系统祖先目录，仅在授权目标读取目录内容；
创建文件用 renameat2 的 RENAME_NOREPLACE 原子提交，避免 SELinux 禁止的硬链接，
并保持目标已存在时不能覆盖的保证。服务与工作目录相邻分开，WebView 的账号存储
也属于 Apps 不可访问的私有基础设施。
账号 bootstrap 只授予确切 loopback origin 主 WebView，普通登录仍写 HttpOnly cookie。
资源预览留在认证 WebView 的 sandbox dialog，外部链接交给系统浏览器。
Android WebView 延伸到系统栏和刘海区域，原生层将安全区几何传给 CSS；标题栏、
抽屉标题、输入区和浮动弹窗分别避让，不给整页增加顶部 padding。原生容器仅为键盘
缩小内容视口，并将已处理的 IME inset 归零后继续传递，避免重复预留和残留留白。
移动抽屉与全屏 Actor 弹窗覆盖内容视口，并在自己的标题与底部控件处理安全区。
Android 默认网络回调将网络与地址变化合并 300 毫秒后通过 JNI 通知后台，避免依赖
受限的系统目录枚举；Activity 销毁时注销回调，不新增 WebView 网络控制命令。

Android 与其他设备使用同样的执行、同步和投票规则，无移动设备专用成员类型。
新设备同步为 learner；投票权只在授权节点交接时通过 joint membership 转移。
离线设备不能实际投票；修改仲裁成员仍须一致性提交，不能各自按在线列表重算法定人数。
新建的单手机账号初始化持久化单节点仲裁；已有仲裁仍需原有 quorum，不能因设备
断线自行缩成单节点；失联恢复使用明确的本地分支。后台生命周期暂停推理并释放
执行租约，保留输入和中断记录，前台重新参与执行。消息通道保持独立，进程被
Android 回收后按持久化游标重连，不重放未知
App 效果。没有常驻后台服务保证，也不以关闭 sandbox 为代价嵌入 shell。

主窗口标题区与内容融为一体，不显示应用名或状态占位。Windows 使用无系统装饰的
窗口和共用界面中的窗口按钮、拖动区；macOS 使用透明覆盖标题栏与原生红黄绿按钮。
原生窗口命令只操作调用者的主窗口，权限绑定确切对话 origin/路径，不开放任意窗口
定位、文件或进程控制。浏览器入口不渲染窗口控制，关窗仍只隐藏，不停止 Actor。

### Conversation import

Local Codex sessions and archived sessions are discovered through a private filesystem
index, with bounded searchable pages and opaque source IDs. Selection checks file
freshness before and after a scope-checked read; credential files are never indexed.
Unsupported devices (including Android) advertise no import capability and hide
the settings category. Selected Codex rollout JSONL is parsed server-side.
Only user/assistant text is retained, without duplicated Codex event copies,
private reasoning, system/developer instructions, tool protocol or grants.
`GET /v1/imports` advertises availability; `GET /v1/imports/codex` lists sources.
`POST /v1/imports/codex/preview` accepts only a listed source ID and stores immutable, Actor-scoped conversation
evidence and returns its opaque resource ID, title and message count.
`POST /v1/imports/codex` submits it to Core through the normal durable user inbox,
using the resource identity for idempotency. Core reads the evidence and chooses
an explicit device, name and factual context through Actors `import_conversation`.
Creation inherits device/parent grants and the current workspace, retains the
original resource in the new Actor ledger, and leaves the inbox empty. Retrying
creation for that input returns the same Actor. Import inputs cannot create via
the ordinary tool, send/cancel delegated work, be edited or become steering.
They remain cancellable. No foreign effects are replayed or provider transcripts
injected into inference history. The shared WebUI renders a compact import card
from the attachment's semantic media type, including queue/search/history previews.
